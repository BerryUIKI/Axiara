# Axiara Batch 1 Implementation Plan

## Overview

Batch 1 focuses on three core components:
1. **Storage Layer** - File-first storage with permission enforcement, SQLite cache, and manifest
2. **Init Script Enhancement** - Language-to-currency inference and workspace.config.yaml export
3. **Crawler Engine** - 7-step pipeline for commodity price fetching

**Target Branch**: Create `feat/core-batch-1` from current `feat/skill-enhancement`

## 1. Storage Layer Implementation

### 1.1 Architecture Enhancements

**Location**: `src/axiara/core/storage/`

**New Components**:

1. **Permission Enforcement** (`permissions.py`)
   - `PermissionManager` class to enforce write rules per DataLayer
   - MAIN layer: write-rejected (human-only)
   - LEARN/MARKET layers: allowed with constraints
   - Defense-in-depth approach

2. **SQLite Cache** (`cache.py`)
   - `SQLiteCache` class for fast queries
   - Auto-synced from CSV/JSON files in `store/`
   - Located at `.data/cache/axiara_cache.db`
   - Read-through cache pattern

3. **Manifest Management** (`manifest.py`)
   - `ManifestManager` class for SHA-256 checksums
   - Stored in `.data/db_dump/manifest.json`
   - Detects unauthorized baseline changes
   - Supports snapshot/recovery

4. **Git-Synced Store** (`git_sync.py`)
   - `GitSyncManager` class
   - Handles `store/` directory as git repo
   - Pull on startup, push on explicit user action
   - Conflict detection and reporting

5. **File Storage Backend** (`file_backend.py`)
   - CSV, JSON, YAML file support
   - Extends current `LocalStorage`
   - Auto-converts between formats
   - Integrates with SQLite cache

### 1.2 Updated Storage Interface

```python
class StorageBackend(Protocol):
    def read(self, layer: DataLayer, key: str) -> Any: ...
    def write(self, layer: DataLayer, key: str, value: Any, user_confirmed: bool = False) -> None: ...
    def list(self, layer: DataLayer, pattern: str = "*") -> list[str]: ...
    def delete(self, layer: DataLayer, key: str, user_confirmed: bool = False) -> None: ...
    def verify_manifest(self, layer: DataLayer) -> bool: ...
```

### 1.3 Tests

- `tests/test_storage_permissions.py` - Permission enforcement
- `tests/test_storage_cache.py` - SQLite cache operations
- `tests/test_storage_manifest.py` - Manifest creation/verification
- `tests/test_storage_git_sync.py` - Git sync scenarios

## 3. Crawler Engine Implementation

### 3.1 Pipeline Architecture

**Location**: `src/axiara/core/crawler/`

**Components**:

1. **Pipeline Orchestrator** (`pipeline.py`)
   - `CrawlerPipeline` class
   - Executes 7-step sequence
   - LangGraph node integration
   - `interrupt()` for user confirmation

2. **Prepare Step** (`prepare.py`)
   - Source registry loader (from `skills/price-crawler/config/sources.yaml`)
   - Robots.txt checker (reuse `scripts/check_robots.py` logic)
   - URL composition
   - Source enablement validation

3. **Fetch Step** (`fetch.py`)
   - HTTP client (httpx) with retry/backoff
   - Browser automation hook (for JS-rendered sources)
   - Rate limiting and delay management
   - User-Agent configuration
   - Error handling and logging

4. **Parse Step** (`parse.py`)
   - Site adapter loader (from `skills/price-crawler/config/adapters.yaml`)
   - CSS/XPath selector-based parsers
   - Named custom parser support
   - Raw row extraction
   - Parse error handling

5. **Normalize Step** (`normalize.py`)
   - Load normalization dictionary (from `skills/price-crawler/config/normalization.yaml`)
   - Alias → canonical mapping
   - Currency normalization
   - Confidence assignment
   - Unknown alias flagging

6. **Dedup/Denoise Step** (`dedup.py`)
   - Key generation: `(name, spec, unit, currency, source)`
   - Duplicate detection and merging
   - Anomaly filter (median range [0.1×, 10×])
   - Quarantine mechanism

7. **Confirm Step** (`confirm.py`)
   - LangGraph `interrupt()` integration
   - Diff calculation vs existing `data/market/`
   - User choice: accept/edit/reject
   - Audit trail

8. **Store Step** (`store.py`)
   - Write to `data/market/<source>/<yyyymmdd>-<material>.json`
   - Raw capture preservation
   - Manifest update
   - Ledger entry

### 3.2 Data Models
